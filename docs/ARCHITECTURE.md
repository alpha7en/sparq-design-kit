# Архитектура SPARQ Studio

## Идея
Модель (Claude) не изучает Figma каждый раз и не рисует вручную: она пишет короткие JSON-спецификации, а сервер подставляет запечатанный рантайм и ассеты и выполняет их в Figma через мост. Токены модели тратятся на смысл (спецификация ~1–2 КБ на слайд), а не на дизайн-код (~80 КБ рантайма уходит в Figma напрямую).

```
Claude ──(MCP: sparq_*)──► sparq-mcp.mjs ──(WebSocket 9223–9232)──► SPARQ Studio Bridge (Figma Desktop)
             ▲                    │  читает design/: tokens, runtime/*.js, icons, library
     skills/commands/agent        └─ картинки с диска → base64 → figma.createImage
```

## Слои
1. **Плагин Claude** (`plugins/sparq-studio`): `skills/` — процедуры и правила с прогрессивной загрузкой (SKILL.md ≈ 450–500 слов, справочники по запросу, примеры grep-ом); `commands/` — входы в режимы; `agents/` — независимая проверка (`sparq-critic` дизайн, `sparq-copy-critic` тексты, `sparq-fact-checker` цифры и свежесть); `hooks/` — короткий контекст на старте.
2. **MCP-сервер** (`mcp/` → `server/sparq-mcp.mjs`): форк figma-console-mcp. Из ~100 исходных инструментов оставлено 16 нужных (остальные — `SPARQ_TOOLSET=full`), добавлены `sparq_*` (`mcp/src/sparq/`). Инструкции сервера — короткий указатель на скиллы.
3. **Рантайм в Figma** (`design/runtime`): `deck/kit.js` (токены, текст, фреймы, иконки, картинки, слайды), `deck/dsl.js` (блоки и макеты), `common/audit.js` (вёрстка), `install/tokens.js`, `install/library.js` (компоненты из снимка), `cards/*` (система карточек: ops, генераторы графиков, lint), `maint/*` (выгрузка источников).
4. **Ассеты** (`design/tokens`, `icons`, `library`): собираются `tools/build-design.mjs` из сырых выгрузок `design/_source`.

## Решения
- **Дизайн в коде, а не в шаблонном файле.** Токены и стили ставятся в любой файл; компоненты карточек восстанавливаются из JSON-снимка (`library/cards.json`, 292 компонента с вариантами, свойствами, вложенными инстансами, привязками к переменным и стилям). Файл SPARQ.2 framework — витрина и источник для обновлений, не зависимость.
- **Код рантайма не хранится в файле** (кроме карточек: их `ops` исторически читает модули из plugin data — установщик пишет их туда). Сервер подставляет актуальный рантайм в каждый вызов, поэтому обновление плагина сразу действует во всех файлах.
- **Защита ручных правок.** После сборки слайда сохраняется снимок его текстов; перед пересборкой сервер сравнивает и, если пользователь правил руками, возвращает правки модели вместо перезаписи.
- **Проверки встроены в сборку**: каждый `sparq_slides` возвращает переполнение, наезды, касания, переносы, пустоты и редакторский lint — модель исправляет до скриншота.
- **Без HTTP-костылей.** Картинки читаются сервером с диска и передаются в Figma внутри кода (base64), локальный файловый сервер не нужен.
- **Порты.** Мост сканирует 9223–9232 и подключается ко всем серверам, поэтому SPARQ Studio может работать рядом с исходным figma-console.
