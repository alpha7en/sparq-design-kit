# Шаблоны слайдов (рецепты)

Каждый рецепт — проверенная компоновка. Полные спецификации живых слайдов: `examples/pitch-deck-accelerator.jsonl` (одна строка = слайд, искать `grep '"key":"S06"'`). Брать рецепт по смыслу блока, а не «для красоты»; менять смело, если содержание просит другого.

## Как выбирать
- Один крупный жест на слайд: число-герой, схема, инверсная плашка или картинка. Второй жест — шум.
- Перечень из 3–5 однородных пунктов → `list` с иконками; последовательность → `steps`/`list num`; сравнение → `table`/`compare`; доли → `stack`/`donut`; «N из M» → `people`; уровень → `scale`; время → `timeline`.
- Слайд из одного текста недопустим: добавь иконки к пунктам, вынеси цифру в `kpi`, превращай перечень в схему.
- **Отчёт ≠ питч.** Аналитический отчёт (voice `report`): навигация обязательна (хаб + входы в главы), термины объясняются в начале главы (не слайд-глоссарий), без грифов и формальностей, кейсы не загонять в одну схему, общие выводы — отправная точка, ценность — кейсы, цифры и схемы. Мало материала — сжать, объединить, убрать слайд. Питч (voice `pitch`): каждый слайд отвечает на вопрос жюри/инвестора по ТЗ, «мы» допустимо.
- Светлая тема — 3–6 слайдов на колоду (таблицы, скриншоты, дорожная карта) для ритма; остальное тёмное.

## Паттерны аналитического отчёта (опыт X5: 39 слайдов, образец стиля)
Отчёт плотнее питча: больше схем и таблиц, меньше слов; навигация обязательна. Источник правил — отчёт X5; собирается теми же блоками.
| паттерн | как собрать |
|---|---|
| обложка отчёта | `cover`, `illus:"barcode-sphere"`, kicker «аналитический отчёт», заголовок до 3 строк, subtitle, строка о команде вместо даты |
| содержание + навигатор | `toc` (номера глав, страницы) + `waffle` «карта отчёта» (клетка = страница); плитки 2×4: иконка + название + страницы |
| «главное» | сетка карточек-выводов: `kpi` (число-герой) + подпись + одна фраза + чип «→ с.»; у плиток мини-графика (`viz`: donut, people, scale, bar, stack) |
| вход в главу | `layout:"chapter"`, иллюстрация главы (`landscape` — вычисления, `contours` — защита данных, `atom` — сенсоры, `sphere`, `network`), «в главе» строками, снизу «термины главы» 5 колонок (`row` из `col`: kicker + text) |
| зрелость | `range` (УГТ 1–9, зона 7–9 — готовое) + плашка-определение `banner` во всю ширину |
| матрица применимости | светлый слайд; `table` с `mark` (сейчас · 3–5 лет · 5+ — белые/чёрные, не красные), надзаголовки групп колонок, `legend` в `aside`; красная полоса — только высокий приоритет |
| хаб | `hub`: центр «выбор при ограничениях», классы вокруг, одна акцентная нить |
| кейс-карточка | `card`: название (`heading`), `chips` (страна · стадия · «данные поставщика»), `kpis`, текст ≤ 3 строк, блок «что показывает» (`banner`) прижат к низу; логотип партнёра справа вверху |
| было → стало | `bars` двух цветов или `compare`; одна цифра — один раз на слайде |
| чек-лист | `list marker:"num"` + плашка-стоп `banner` |
| сводка | `table` с фактическими колонками (стадия лучшего кейса, с чем пилотировать, российские решения, условие) — не балльные оценки |
| источники | `sources`, светлый слайд |
Схемы без блока (граф с толщиной связей, лестница, схема сети с нумерованными бейджами, карта городов) — свободный режим `sparq_run {kit:"deck"}` по описанию в справочнике X5 («знаки и маркеры», «типы диаграмм»). Правила: один крупный жест на слайд; красный — метка, а не заливка; контейнер только если он группирует; ≤ ~150 знаков текста в карточке при трёх колонках; заголовок слайда ≤ 45 знаков.
