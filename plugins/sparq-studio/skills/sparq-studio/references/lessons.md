# Уроки из правок заказчика (важнее общих гайдов)

Выучено на живых правках: карусели «рынок квантов», отчёт для X5 (49 слайдов), питч-дек для акселератора Газпромбанка (18 слайдов). Если правило здесь расходится со справочником — прав этот файл.

## Процесс
- **ТЗ исполняется поблочно и буквально.** Перед сдачей сверить каждый слайд/карточку с пунктом ТЗ: про то ли он. Финальный текст из ТЗ не переписывать — только сокращать по указаниям.
- **Не смешивать темы**, которые пользователь назвал самостоятельными.
- «Не меняй, дай варианты» = варианты в чате, файлы не трогать. Варианты — с характером, не тянуть к безопасной середине.
- **Комментарии Figma читать механически** (`sparq_comments`), а не по памяти: при возвращении к работе и перед каждым отчётом. Непрочитанный комментарий + «готово» = провал.
- **Приёмка накопительная.** Итерацию проверять целиком, парами «было | стало»: сверху вниз — сценарий → визуальная идея → мелочи. Мелкие исправления не выдавать за победу. Одобренное не трогать без просьбы.
- **Правка «везде» — везде.** Нашёл класс ошибки в одном месте → искать по всей работе (`sparq_audit` без ключей, поиск текста).
- **Ручные правки пользователя священны.** Перед пересборкой сравнить; `sparq_slides` сам останавливается (`manualEdits`) — перенести правки в спецификацию.
- **Короткие круги на реальном материале** вместо «огромного конструктора»: собрать → пользователь комментирует → закрепить одобренное.
- Сборщик не бывает сам себе критиком: перед сдачей — агент `sparq-critic`, для текстов — `sparq-copy-critic`, для цифр — `sparq-fact-checker`.
- Ответы пользователю — коротко и по делу, без перечней реквизитов и id.

## Факты и источники
- Нет файла/ссылки — нет факта. Цифра = источник дословно: «до», «около», год и чья оценка — как в источнике; диапазон не превращать в точку.
- Конкретика: какая лаборатория, компания, прибор, год. В сравнениях — все ключевые игроки, не случайная выборка.
- **Свежесть:** перед финалом — новости по теме за 30–60 дней; событие, опровергающее рамку, меняет текст.
- Корпоративные цифры — с атрибуцией («по данным компании»), одинаково для всех игроков. Кратности — только в одной метрике.
- Источник на каждой карточке — нельзя; @-ники на карточках читаются как коллаборация. В слайдах — короткая сноска `foot`, полный список — слайд «Источники».
- Оценки «по аналогии» ради заполнения схемы не выдумывать. Цифры-прогнозы для компании заказчика — нельзя; цифры кейсов и рынка — да.
- Жёсткое «не доказано» → «есть наработки, но на ранней стадии / слабее, чем X».

## Текст
- Термин не объяснён → заменить смыслом, а не добавлять определение. Не заканчивать блок узким термином.
- Без вычурных метафор и без детского языка — точный технический, понятный «с холода».
- У каждого утверждения есть подлежащее; понятие объясняется механизмом («кто, что, почему»), а не ярлыком.
- Сначала суть (что сделано, как), потом мета (что не раскрыто, спор формулировок) — максимум одна карточка.
- «Зачем это читателю» — одной фразой в первых двух карточках/слайдах.
- Без очевидных выводов («квантовые технологии — это четыре направления»), без слоганов в заголовках, без мета-строк («ниже — наблюдения»), без «не X, а Y», без самолюбования («42 из 60»).
- Тон по российской тематике — без катастрофизма: проблема как толчок другим направлениям + кейсы.
- Без шаблонности: не загонять каждый кейс в одну схему; мало сказать — сжать, объединить, убрать.

## Драматургия
- Каждый блок вносит новое и раскрывает его данными; переходы — одна фраза-мысль.
- Порядок и настроение задаёт бриф; финал «почему так» не обязателен; контекст может стоять в начале.
- Карусель — не стопка простыней: 1–2 лёгкие карточки (цитата, одно число, схема) на 2–3 месте.
- Рубрика = формат (новость, explain, серия); новость начинается с события и первоисточника.
- Если у первоисточника нет содержания — сказать прямо и предложить другой угол, а не строить пост вокруг пустоты.
- Большой отчёт (25+ слайдов) — навигация: хаб + входы в главы, а не только оглавление.

## Графика и дизайн
- **Пятен и ярких красных точек нет.** Красная дымка, размытые красные шары, стекло на красном пятне, светящиеся красные точки-узлы на фонах — запрещены в карточках и слайдах (замечание повторялось много раз). Красный — тонкая линия, одна неоновая дуга обложки, число-герой, один столбик графика. Пятно допустимо только едва заметной подсветкой внутри отдельной плашки. Иллюстрации X5 несут один красный акцент по смыслу (вектор состояния, решение, хаб) — это не фон.
- **Использовать весь набор активов, а не обходить его.** Перед сдачей спроси себя: есть ли у обложек иллюстрации по теме, у списков — иконки, у перечней цифр — инфографика, у глав — вход с иллюстрацией, у длинного отчёта — навигация. «Текст на чёрном» — не результат.
- **Эталон стиля — отчёт X5** (плотный, со схемами и иллюстрациями), а не питч Газпромбанка; питч проще и легче.
- Обрубки (вырезанные куски символов, обрезанные подписи, слова, рвущиеся посередине) — брак; заголовок подбирается по ширине, иллюстрация целиком.
- Графика показывает то, чего нет в тексте; пересказ одной фразы картинкой — брак. Столько чисел, сколько нужно одной мысли; много данных — больше элементов, а не урезание.
- Стильно **и** читаемо: контраст (основной ≥ 7:1, подписи ≥ 4.5:1), ч/б-проверка иерархии, превью на телефоне 390 px для карточек. Нельзя: чёрный текст на ярко-красном, длинный белый текст по красному, больше одного «самого яркого» элемента.
- Один герой на карточку/слайд. Плашки — только когда группируют; иерархия — кеглем и позицией.
- Ничего не касается краёв и соседей; нет переносов внутри слова; зазор между блоками ≥ их внутреннего отступа («внутреннее < внешнего»).
- Фон — под содержание, шапка — под фон: декор не заходит под рубрику, знак, текст, график; пятна дымки едва заметны.
- Пустые тёмные провалы — брак; «текст на чёрном» — не дизайн. Мало знаков → иконки к перечням, цифрам — инфографика.
- Читаемость важнее плотности: лучше больше карточек/слайдов, чем меньше кегль.
- Интерфейсные макеты (платформа arena): без зерна и дымки, без подложек «цвет на цвете»; статус — цветная иконка или цифра на нейтральном фоне.
