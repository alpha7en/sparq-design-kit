# SPARQ Studio · старт, состояние, режимы

SPARQ Studio — студия дизайна в стиле SPARQ для Figma Desktop: презентации 1920×1080 и карусели карточек 1080² для Telegram. Внутри плагина свой мост к Figma (MCP-сервер `sparq`), запечатанная дизайн-система и проверки качества. Пользователь — дизайнер или автор, не программист: объяснять по-человечески, коротко, без JSON и id.

## В начале каждой работы с Figma
1. `sparq_status`. Пересказать одной-двумя фразами: подключён ли мост, какие файлы открыты, какой активен, что в них установлено (deck / cards / ничего).
2. Мост не подключён → провести по `references/setup.md` (шаг за шагом, по одному действию, ждать подтверждения).
3. Выбрать файл: если открыто несколько — спросить, с каким работать, и закрепить `sparq_use_file`. Активный файл может смениться, если пользователь кликнул в другой файл — после пауз проверять `sparq_status` снова.
4. Определить режим и загрузить скилл:
   - презентация, слайды, отчёт, питч → **sparq-deck**;
   - карточки, карусель, пост, Telegram → **sparq-cards**;
   - вычитка, редактура, «странные формулировки», тексты → **sparq-editor**.
   Режим переключается по запросу; сказать пользователю, в каком режиме работаем.

## Новый файл
- Презентация: Figma Slides или обычный дизайн-файл → `sparq_setup_file {kit:"deck"}` (секунды).
- Карточки: только дизайн-файл → `sparq_setup_file {kit:"cards"}` (1–2 мин: ставит токены, генераторы и страницу-библиотеку «SPARQ · система 1:1»). Предупредить о времени.
- Повторный запуск безопасен. Если ответ говорит «outdated» — библиотека в файле старше плагина: повторить с `replaceLibrary:true`.

## Общий цикл качества (для любого режима)
сборка инструментом → разбор `issues`/`lint` → правка → скриншот (scale 0.5–0.8) и взгляд глазами → вычитка → короткий отчёт. Никогда не называть работу готовой без просмотренного скриншота. Аккуратность важнее выразительности.

## Экономия контекста
- Не читать справочники целиком без нужды; брать нужный раздел (grep).
- Не исследовать Figma через `sparq_run`, если ответ даёт `sparq_status`, `sparq_catalog` или справочник.
- Скриншоты — scale ≤ 0.8; детали — кадр узла, а не всего слайда в scale 1.
- Длинные ответы инструментов не пересказывать пользователю — только вывод.

## Комментарии и обратная связь
`sparq_comments` (нужен токен Figma в `~/.sparq-studio/figma-token`, см. setup). Каждый комментарий разбирается по протоколу `references/workflow.md`: текст → правка, композиция → другой вариант из каталога, дефект системы → сказать, не латать вручную.

## Ресурсы
- `references/workflow.md` — работа с ТЗ, протокол комментариев, приёмка, безопасность. Прочитать перед первой работой в сессии.
- `references/setup.md` — установка, подключение Figma, токен, частые проблемы.
- `references/tools.md` — все инструменты `sparq_*` и оставленные `figma_*`, когда что вызывать.
